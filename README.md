# Финальный проект — BMC DevOps задание

## Что сделано

- Верстка сайта хранится в Mercurial-репозитории с историей из 6 коммитов, включая слияние ветки `feature` в `default`.
- Собран Docker-образ на основе `nginx:alpine`, включающий верстку через `COPY`.
- Образ отправлен в собственный приватный Docker registry, поднятый локально на порту 5000.
- Сайт развёрнут как сервис в Docker Swarm через `docker-compose.yaml`, 2 реплики.
- Доступ на сервер организован только по SSH-ключу (парольная аутентификация отключена).
- Firewall (ufw) открывает только необходимые порты: 22 (SSH), 80 (HTTP), 2377/tcp, 7946, 4789/udp (Swarm), 5000 (registry), 8000 (hg serve).
- Настроен скрипт автоматического бэкапа верстки (`backup.sh`) с ежедневным запуском через cron в 02:00.

## Основные команды

- `hg log` — история коммитов
- `docker build -t localhost:5000/my-site:1.1 .` — сборка образа
- `docker push localhost:5000/my-site:1.1` — отправка в registry
- `docker stack deploy -c docker-compose.yaml mystack` — деплой стека
- `docker stack ps mystack` — проверка состояния реплик
- `./backup.sh` — ручной запуск бэкапа
- `crontab -l` — просмотр расписания автозапуска

## Возникшие проблемы и решения

1. **Порт 8080 (и позже 5000, 8000) не был открыт в ufw** — сайт/сервис были недоступны снаружи VM, хотя внутри работали. Решено открытием портов через `sudo ufw allow <порт>`.
2. **ssh-copy-id не сработал** — у пользователя `ubuntu` в Multipass нет пароля. Решено ручным добавлением публичного ключа в `~/.ssh/authorized_keys`.
3. **PasswordAuthentication no не применялось** — строка в `/etc/ssh/sshd_config` была закомментирована символом `#`. Решено раскомментированием строки и проверкой через `sudo sshd -t` перед перезапуском.
4. **Docker Swarm не обновлял контейнеры на новый контент при том же теге образа** — после пересборки образа под тем же тегом `1.1` Swarm продолжал использовать старый закешированный digest. Решено явным `docker pull` + `docker service update --force --image`.
5. **Chrome не открывал сайт по локальному IP (ERR_ADDRESS_UNREACHABLE)**, хотя `curl` и Safari работали нормально — особенность браузера/расширений, не связанная с сервером.

## Итоговая проверка

- `docker stack ps mystack` показывает 2 работающие реплики
- Сайт открывается по адресу `http://192.168.252.2`
- Вход на сервер — только по SSH-ключу
- Автобэкап настроен через cron
